# 나이트라이더·유니콘·바운싱 나이트라이더·구행·텐쿠·추기경

기존 `PieceDefinition.upgrades`와 `Game::snapshot().upgrade_paths`를 통해 휴식 UI에 연결한다. 추기경 외의 후보는 Chesssembly `Program`이 생성하고, 추기경은 기물 전용 계산기가 같은 `DefaultAction`을 생성한다. 실제 이동은 기존 `Battle::apply_piece_action`과 `apply_default_action`이 다시 검증한다. 두 진영은 같은 기물 정의를 사용한다. DSL 기물은 Chesssembly가, 추기경은 전용 계산기가 상대 좌표의 두 축을 진영에 맞게 뒤집는다.

| ID / key | 기물 | 휴식 선행 기물 | 행마 |
| --- | --- | --- | --- |
| 18 / `knightrider` | 나이트라이더 | 나이트 | 각 나이트 벡터를 독립적으로 반복 |
| 19 / `unicorn` | 유니콘 | 나이트라이더 | 일반 나이트 + 임의 빈칸 이동 |
| 20 / `bouncing_knightrider` | 바운싱 나이트라이더 | 나이트라이더 | 나이트라이더 뒤 최대 한 번 90° 반사 |
| **17 / `hook`** | **구행** | 바운싱 룩 | **기존 정의·ID·보스 재사용** |
| 21 / `tengu` | 텐쿠(天狗) | 바운싱 비숍 | 빈 경유지에서 두 번째 비숍 구간 |
| 22 / `cardinal` | 추기경 | 바운싱 비숍 | 경계·바운싱 폰에서 반복 반사 |

## 사용한 Chesssembly 소스

나이트라이더는 기존 `KNIGHT` 순서의 여덟 벡터마다 아래 독립 체인을 사용한다. `repeat(1)`은 같은 `take-move`를 다시 실행한다. 각 착지에서 이동 후보를 만들고, 아군·적·경계에서 해당 체인이 끝난다. 점프 중간 칸은 조사하지 않는다.

```scss
take-move(-1,2) repeat(1); take-move(1,2) repeat(1);
take-move(-2,1) repeat(1); take-move(2,1) repeat(1);
take-move(-2,-1) repeat(1); take-move(2,-1) repeat(1);
take-move(-1,-2) repeat(1); take-move(1,-2) repeat(1)
```

유니콘은 기존 나이트의 `take-move(dx,dy)` 여덟 체인에 보드의 64칸 각각을 조사하는 `absolute(x,y) move(0,0)` 체인을 더한다. 아래는 생성되는 체인의 형태다. `move`가 점유된 칸을 거부하고, 적용 단계도 빈 목적지만 받는다. 나이트 체인은 포획할 수 있다. 두 경로가 같은 빈 나이트 착지 칸을 가리킬 수 있으나 화면은 목적지별로 표시하며 클릭 시 앞에 놓인 일반 나이트 행동을 실행한다.

```scss
take-move(-1,2); take-move(1,2); ... ; take-move(1,-2);
absolute(0,0) move(0,0); absolute(1,0) move(0,0); ... ; absolute(7,7) move(0,0)
```

바운싱 나이트라이더는 제공된 8방향과 회전 벡터를 그대로 사용한다. 각 행은 다음 템플릿의 별도 체인이다.

```scss
wall-piece(bouncing_pawn)
do take-move(dx,dy) while
enemy(0,0) not barrier(dx,dy)
{ take-move(ax,ay) repeat(1) }
{ take-move(bx,by) repeat(1) }
```

| 접근 `(dx,dy)` | 첫 반사 `(ax,ay)` | 둘째 반사 `(bx,by)` |
| --- | --- | --- |
| `(2,1)` | `(-1,2)` | `(1,-2)` |
| `(2,-1)` | `(-1,-2)` | `(1,2)` |
| `(-2,1)` | `(1,2)` | `(-1,-2)` |
| `(-2,-1)` | `(1,-2)` | `(-1,2)` |
| `(1,2)` | `(-2,1)` | `(2,-1)` |
| `(1,-2)` | `(-2,-1)` | `(2,1)` |
| `(-1,2)` | `(2,1)` | `(-2,-1)` |
| `(-1,-2)` | `(2,-1)` | `(-2,1)` |

원본의 `edge-*`, `jne`, `label`은 현재 파서에서 지원한다. 다만 `edge-*`는 **한 방향만** 넘은 경우에만 참이므로 두 경계를 함께 넘으면 두 분기를 모두 놓친다. 또한 원본은 접근 중 적을 포획하고 `while`을 빠져나온 뒤에도 경계 검사를 계속할 수 있다. 현재 소스는 `barrier`와 두 자식 블록으로 같은 8방향 회전 벡터를 유지하면서 두 경계의 분기를 각각 검사하고, `enemy(0,0) not`으로 포획 후 반사를 막는다. 분기 안에는 다시 분기 명령이 없으므로 한 경로의 반사는 최대 한 번이다. 보드 밖 착지는 `take-move`가 생성하지 않는다.

기존 바운싱 룩·비숍은 아군 바운싱 폰을 반사벽으로 취급하고 적군 바운싱 폰은 포획한다. 이 기물도 같은 `wall-piece(bouncing_pawn)`과 `barrier`를 써서 **착지하려는** 폰 앞에서 반사한다. 나이트 점프의 중간 칸에 있는 폰은 착지 칸이 아니므로 통과한다. 일반 아군은 차단하고, 일반 적은 포획 후 종료한다. 코너나 마스크 경계에서는 두 회전 벡터를 각각 시도하되 유효한 착지만 후보로 남긴다.

구행의 기존 코드는 변경하지 않았다. 접근 방향마다 `do take-move(x,y) { 직각 슬라이드 } { 반대 직각 슬라이드 } while`이며, 빈 경유지에서 멈추거나 한 번 꺾을 수 있다. ID 17과 `hook` key 및 1층 보스 편성을 유지한다.

텐쿠는 구행의 구조를 대각선에 적용한다. 접근 방향 네 개의 각 빈 착지마다 아래 네 자식 블록이 별도 탐색을 한다. 첫 구간 적 포획 시 자식 블록에 들어가지 않는다. 두 번째 구간도 아군·적에서 끝난다.

```scss
do take-move(x,y)
  { take-move(-1,-1) repeat(1) }
  { take-move(-1, 1) repeat(1) }
  { take-move( 1,-1) repeat(1) }
  { take-move( 1, 1) repeat(1) }
while
```

추기경의 계산은 [`cardinal.rs`](../crates/chesslayer/src/content/pieces/cardinal.rs)에 있다. 범용 Chesssembly 식의 유한한 블록·슬롯·반복만으로는 무제한 분기 반사의 `(칸, 다음 진행 방향)` 방문 집합을 정확히 유지하기 어렵다. 따라서 추기경만 전용 네이티브 계산기를 사용한다. Chesssembly 인터프리터에는 추기경 전용 명령이나 실행 분기가 없다.

네 대각 방향에서 각각 시작해 빈 칸마다 `TakeMove` 후보를 낸다. 아군 일반 기물은 차단하고, 적군 일반 기물과 적군 바운싱 폰은 포획 후보를 낸 뒤 그 경로를 끝낸다. 보드 경계·마스크 경계·아군 바운싱 폰 앞에서는 그 칸에 진입하지 않고 가로 또는 세로 성분 하나를 반전한 두 경로를 탐색한다. 같은 `(칸, 다음 진행 방향)`을 다시 만나면 그 분기를 종료하므로 순환해도 유한하게 끝난다. 액션에는 실제 착지 경로가 포함되어 이동 미리보기에서도 확인할 수 있다.

## 검증

`cargo test --workspace --no-fail-fast`로 기존 전투·보스·강화 기보와 신규 테스트를 함께 실행한다. `new_movements.rs`는 백·흑의 나이트 반복 착지, 중간 점프, 차단·포획, 유니콘 빈칸 전용 이동, 바운싱 나이트라이더의 코너와 폰 반사 및 포획 종료, 텐쿠 두 구간, 추기경의 **두 번째 반사 후** 도착과 64개 시작 칸×양측의 종료·액션 적용을 확인한다. 등록 테스트는 모든 ID/key의 유일성, 양측 SVG, 모든 DSL 기물의 파싱과 합법 수 생성, 추기경 전용 계산기의 합법 수 생성을 검사한다. 구행 보스 테스트는 기존 동작을 계속 검사한다.
