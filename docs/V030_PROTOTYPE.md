# v0.3.0 프로토타입 구현 기록

기준은 저장소 루트의 `chesslayer-v0-3-0_기획서.md`다. 확정된 핵심 규칙과 최신 이단 제안안을 구현했다. 보류된 광신도·실수 유발·러시안 룰렛·LSD·폭식은 현행 콘텐츠에 포함하지 않는다.

## 플레이와 저장

수호자만 처음 선택할 수 있다. 정규 층은 각각 보스 포함 15단계다. 1~4층 보스는 선봉대·이단·포병·특수부대 순서다. 보스 승리 즉시 해당 부대만 영구 해금하고, 보상을 마치면 같은 원정에서 다음 층으로 진행한다. 4층 후에는 부족의 독재자와의 최종 결전으로 이어진다. 새 원정은 1층에서 시작하며 해금한 부대는 계속 선택할 수 있다.

해금은 `chesslayer.progress.v1`, 현재 원정은 기존 별도 저장 키에 보존한다. 저장 v15는 시작 부대·층·해금 상태와 명령을 재생한다. v14 원정도 새 규칙으로 재생해 복원한다. 새 원정이 해금 기록을 덮어쓰지 않는다. 규칙이 다른 v13 원정은 재생하지 않으며 새 원정을 시작하기 전까지 원본 저장을 보존한다. 기존 저장의 층 해금 필드는 호환을 위해 읽지만 진행 제한에는 사용하지 않는다.

메인 메뉴 도감은 엔진의 시작 덱·보상 카드풀·유물풀·시작 편성·강화 정의를 읽어 모든 부대의 정보를 공개한다. 기물 행마 예시는 같은 행마 엔진을 빈 보드와 가상 적 배치에 적용한다. 강화 트리는 기존 UI를 읽기 전용으로 사용한다. 카드 자체의 강화판은 현재 정의되어 있지 않다. `찰나의 가호`는 카드 정의가 있지만 현재 획득 경로가 없어 그 상태를 표시한다.

기물 클릭으로 이동하고, 사격/제물은 선택 기물의 **특수 능력**에서 대상을 고른다. 사제·유물 등 후속 효과도 보드에서 대상을 선택한다. 복수 대상 카드는 기물 또는 빈 칸을 고른 후 확정한다. 전선잡기는 배치 완료를 누를 때까지 반복해서 기물과 빈 칸을 선택한다.

## 실제 적용한 내용

- 부대별 시작 편성·덱·보상 카드풀·유물풀. 신규 기물 48종은 각자의 정의 파일과 행마 스크립트를 가진다. 전체 기물 82종, 카드 34종, 유물 20종이다.
- 선봉대의 고유 9종 행마/강화, 권총, 부대 2행동, 민첩·약화, 희생·증원·마지막 저항, 전투 후 충원 선택.
- 이단의 별도 중립 시체, 식재료 포획 시 제자리 시체화, 양측 시체 포획, 축복·과흥분, 광기 전향, 죄책감 전투불능, 단계형 허기 지속/제약. 이단 6계열의 전체 강화와 카드·유물 효과.
- 고해성사만 영구 전투불능을 해제한다. 식당은 허기만 제거한다. 마지막 접시는 해당 전투의 허기 악화 1건을 선택해 막는다.
- 이단 보스의 정확한 16기+시체 2기 배치, 주빈의 축배 첫 3회, 2·5수 예고와 3·6수 종소리.
- 포병의 사격·탄약 지속, 창고 한계/폭발/전멸 패배, 창고 강화, 일제사격 실제 처치 수 비용과 반복 재배치.
- 특수부대의 소수 편성·사격·기동·연막·전용 강화. 층 3·4의 일반/정예 전투와 별도 최종 보스.
- 상태 표시, 특수능력 명중률, 새 기물 양 진영 SVG 96개, 카드·유물 그림, 강화 확정, 보상/상점/식당/휴식과 저장 연결.

## 검증

2026-10-30 검증: Rust 전체 테스트 **103개 통과**, 전체 타깃 Clippy 경고 없음, Rust/WASM 빌드 및 웹 TypeScript·Vite 프로덕션 빌드 성공. Chromium에서 실제 조작 스모크를 수행했다.

`cargo test --workspace`, `cargo check --workspace --target wasm32-unknown-unknown`, `cargo clippy --workspace --all-targets -- -D warnings`, WASM 생성 및 웹 프로덕션 빌드로 검증했다. 신규 테스트는 4개 통합 스모크와 3개 전투 핵심 스모크로 한정했다. 오래된 테스트의 14단계/동일 부대/연속 층 이동 기대값은 새 규칙으로 수정했다.

브라우저에서 부대 잠금, 수호자 실제 이동과 적 턴, 모든 부대 시작/새로고침 복원, 제물→시체, 복수 카드 선택·소멸, 민첩, 사격과 탄약, 반복 배치, 별도 최종 결전 진입을 확인했다. 장기 플레이 난이도와 미정 부대의 수치 균형은 확정하지 않았다.
# 드론·전차 강화와 전투 효과 (2026-10-30)

- 드론은 수류탄 → C4 → 전술핵, 수류탄 → 기관총 → 유탄발사기 두 분기다. 모든 단계는 원래 드론의 행마 스크립트를 공유한다. 수류탄·기관총·유탄발사기는 직교 자폭, C4는 킹 범위 자폭, 전술핵은 킹+나이트 범위 자폭을 사용한다. 자폭은 명중 판정 없이 아군·적군·시전자를 제거한다.
- 전차는 고폭탄 → 쌍열포, 철갑탄 → 파편 첨가물 두 분기다. 모든 단계는 원래 전차 행마를 공유한다. 고폭탄과 유탄발사기의 명중 후 폭발은 탄착 칸과 직교 인접 칸을 확정 제거한다. 쌍열포는 템페스트 룩의 기존 행마 프로그램을 사격 대상 계산에 사용한다.
- 공통 관통경로는 시작 칸, 방향 목록, 최초 관통 확률, 성공당 감쇄율, 허용 진영을 받는다. 빈칸은 확률을 소모하지 않고 실패한 경로만 멈춘다. 철갑탄은 직진 80/60/40/20%, 파편은 최초 명중 칸에서 직진·좌우 45도 세 갈래로 각각 75/50/25%다.
- 방사성 낙진은 전투 보드 칸에 남고, 해당 진영의 턴 종료 때 그 칸에 있는 기물을 제거한다. 지속시간 상수는 `FALLOUT_ROUNDS`로 관리한다. 폭발이 적 턴에 발생하면 그 턴의 종료를 지속시간에 포함하지 않으며, 이후 두 라운드 경계가 지난 뒤 제거한다. 전투 종료 시 낙진을 비우고 다음 전투는 새 전투 상태로 시작한다.
- 명세에 유탄발사기의 별도 사거리·명중률 수치가 없어 기관총 드론의 직교 4칸·기본 90%·탄약 1을 사용하고, 탄착 효과만 고폭탄과 동일하게 정했다. 자폭과 탄착 폭발의 기존 `식재료` 시체 전환은 적용하지 않고 즉시 제거한다. 창고의 기존 연쇄 폭발은 유지한다. 동시 로얄 제거 시 엔진의 아군 패배 우선순위를 유지한다.

핵심 판정 테스트는 `crates/chesslayer/src/battle/mechanics.rs`의 `ordnance_tests`에 둔다. `cargo test -p chesslayer --lib ordnance_tests`로 범위·양 진영 피해·동시 로얄 승패·낙진 지속과 종료 피해·고폭탄 명중/빗나감·쌍열포 사거리·관통 확률과 상대 방향 분기를 확인한다.
테스트장 조작은 `web/tests/drone-tank.spec.ts`의 Playwright 시나리오로 확인한다. 두 강화 트리 전환, 기관총의 별도 능력 버튼, 전술핵 범위·낙진 표시, 파편의 세 갈래 색상 구분을 검증한다.
