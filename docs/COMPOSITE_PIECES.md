# 상위 복합 기물과 강화 트리

새 ID는 23–30이다. 기존 기물 ID와 보스 구행(17)의 행마는 유지한다. 모든 강화는 `PieceDefinition.upgrades`의 한 간선이며, 쉼터의 살아 있는 출발 기물 하나와 행동 1회가 필요하다. 아래에서 별도로 적은 동시 보유 조건은 Rust 원정 상태가 검사한다.

| 출발 | 도착 | 추가 영구 로스터 조건 |
| --- | --- | --- |
| 폰 | 템페스트 폰, 바운싱 폰 | 없음 |
| 나이트 | 템페스트 나이트, 나이트라이더 | 없음 |
| 템페스트 나이트 | 태풍 나이트 (30) | 없음 |
| 나이트라이더 | 유니콘, 바운싱 나이트라이더 | 없음 |
| 비숍 | 템페스트 비숍, 바운싱 비숍 | 없음 |
| 템페스트 비숍 | 바운싱 템페스트 비숍 (26) | 템페스트 비숍 + 바운싱 비숍 |
| 템페스트 비숍 | 태풍 비숍 (29) | 없음 |
| 바운싱 비숍 | 텐쿠, 추기경 | 없음 |
| 룩 | 템페스트 룩, 바운싱 룩 | 없음 |
| 템페스트 룩 | 바운싱 템페스트 룩 (25) | 템페스트 룩 + 바운싱 룩 |
| 템페스트 룩 | 태풍 룩 (28) | 없음 |
| 바운싱 룩 | 구행 | 없음 |
| 퀸 | 템페스트 퀸, 바운싱 퀸 | 없음 |
| 템페스트 퀸 | 바운싱 템페스트 퀸 (24) | 템페스트 퀸 + 바운싱 퀸 |
| 템페스트 퀸 | 태풍 퀸 (27) | 없음 |
| 바운싱 퀸 | 행마의 신 (23) | 구행 + 텐쿠 |

쉼터 화면에는 잠긴 가지도 보인다. Rust가 보내는 `required_pieces`에는 각 선행 종류의 현재 영구 보유 여부가 포함된다. 노드 툴팁과 상세 창이 이를 표시한다. 출발 기물은 살아 있어야 한다. 다른 선행 기물은 사망 기록이어도 보유로 인정한다. 전투 중 승격·카드 임시 강화는 보유 종류를 바꾸지 않으며 해금에 사용되지 않는다. 선행 기물은 소비되지 않는다. 이미 확정된 영구 강화는 이후 로스터 조건이 달라져도 되돌리지 않는다.

## 행마 구성

- **행마의 신:** 구행과 텐쿠의 DSL 체인을 합친다. 동일 목적지·행동 효과 후보는 기존 `Battle::legal_actions`의 액션 중복 제거로 한 번만 제시한다.
- **바운싱 템페스트 퀸·룩·비숍:** 템페스트의 첫 경유 칸과 두 분기를 유지한다. 각 실제 분기 광선에는 기존 바운싱 회전 벡터와 `wall-piece(bouncing_pawn)` 판정을 적용한다. 첫 경유 칸 진입 자체가 경계나 아군 바운싱 폰에 막힌 경우에도 그 경로에서 한 번 반사한다. 적군 바운싱 폰은 포획하고 경로를 종료한다. 반사 뒤에는 직진하고 다음 벽에서 끝난다. 중간 포획 뒤 분기는 열리지 않는다. 퀸은 이 복합 경로를 자체 정의에 보유한다.
- **태풍 퀸:** 템페스트 퀸 + 일반 룩 + 일반 비숍.
- **태풍 룩·비숍·나이트:** 각각 해당 템페스트 행마 + 같은 종류의 일반 행마.

새 기물은 각자 정의 파일과 백·흑 SVG를 가진다. SVG는 기존 벡터 실루엣에 계열별 배지를 더했으며 출처는 `web/src/assets/pieces/provenance.json`에 기록한다. 전체 트리는 23개 간선이며 순환이 없다.

## 검증

- `cargo test -p chesslayer --test composite_pieces`: 양측 진영의 행마 합집합, 템페스트 경유·포획, 실제 경로 반사와 두 번째 벽 종료, 잠금·사망 보유·일시 승격 제외, 트리 순환을 검사한다.
- `cargo test --workspace --no-fail-fast`: 기존 보스 구행, 원래 기물, 전투·쉼터 동작을 함께 회귀 검사한다.
- `cd web && npm run wasm && npm run build`: 웹용 Rust 빌드와 TypeScript·자산 번들을 확인한다.
- `cd web && npx playwright test tests/rest.spec.ts`: 트리 노드, 잠금 조건, SVG 미리보기, 기존 확정·저장 흐름을 확인한다.
