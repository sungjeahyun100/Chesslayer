# 신규 콘텐츠 시각 통합과 확인 방법

## 구현 위치

| 콘텐츠 | 자산 | 화면 연결 |
| --- | --- | --- |
| 카드 5종과 기존 카드 4종 | `web/src/assets/cards/<kind>.svg` | 손패·혼합 보상의 카드 그림, 이름·비용·효과 설명 |
| 신규 유물 5종과 기존 시작 유물 3종 | `web/src/assets/relics/<id>.svg` | 캐릭터 선택·보상·보물·보유 목록·상태 설명 |
| 신규 기물 13종, 각 백·흑 | `web/src/assets/pieces/<key>-white.svg`, `<key>-black.svg` | 전투 보드·선택 정보·승격·휴식·강화 트리 |
| 구행 | 기존 `hook-white.svg`, `hook-black.svg` | 전투 보스·기물 설명 |

카드 그림은 항상 카드 본문 위의 독립 영역에 놓는다. 일시 강화는 대상별 경로를 확정하면 손패 카드의 비용 원형이 `N`에서 선택 수로 바뀐다. 비용과 효과 설명은 Rust 카드 정의가 제공한다. 전투 효과 목록과 기물 배지에는 리미터의 남은 이동 횟수·0회 도달 시 사망과 턴 종료, 일시 강화, 가호를 표시한다. 유물 목록의 선공권·아이스크림·진형 상태 문구는 Rust 스냅샷이 제공한다.

## 자동 검증

저장소 루트에서 실행한다. 현재 저장 기록은 버전 8이며 이전 버전은 현재 규칙으로 자동 이관하지 않는다.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo check --workspace --target wasm32-unknown-unknown
npm run wasm --prefix web
npm run build --prefix web
CHESSLAYER_CHROME=/usr/bin/google-chrome npm run test:e2e --prefix web
git diff --check
```

브라우저 검사는 localhost 바인딩이 허용되는 환경에서 실행한다. 이번 작업에서 Rust 전체 테스트, Clippy, TypeScript/Vite 빌드, 실제 Chrome E2E **18개**가 통과했다. E2E는 빈 초기 덱, 첫 승리와 카드·유물 혼합 보상, 획득 후 다음 전투, 다중 대상 일시 강화, 휴식 분기와 해금, 보스 완주, 저장 복원, 390px 모바일 화면을 포함한다. 보상 테스트는 각 선택 카드의 SVG가 실제 로드되는지 확인한다. 기물 SVG 60개, 카드 SVG 9개, 유물 SVG 9개는 XML 파싱을 확인했다.

현재 작업 환경의 `wasm-pack` 설치 캐시는 읽기 전용이라 기본 `npm run wasm`은 바인딩 CLI 자동 설치 단계에서 실패했다. Cargo.lock과 같은 버전의 CLI가 이미 있는 `/tmp/chesslayer-tools/bin`을 PATH에 넣고 `wasm-pack build crates/chesslayer-web --target web --out-dir ../../web/src/wasm --release --mode no-install`로 동일한 바인딩을 생성해 검사했다. 일반 개발 환경에서는 위 표준 명령을 그대로 사용하면 된다.

## 수동 확인 절차와 기대 결과

1. `npm run dev --prefix web`을 실행하고 새 원정을 시작한다. 세 캐릭터의 시작 유물 아이콘이 표시되어야 한다. 아무 시작 전투 노드를 선택하면 **손패 0/10**과 빈 손패 안내가 나오고 보드·턴 버튼이 정상 작동해야 한다.
2. 첫 로얄을 포획한다. 보상 카드 3장은 카드·유물이 섞여도 데스크톱에서 같은 폭·높이로 정렬되고 모바일에서는 한 열로 표시되어야 한다. 모든 선택지에 이미지·이름·비용 또는 유물 유형·설명이 보여야 한다. 그림과 설명은 서로 겹치지 않는다. 카드와 유물을 각각 선택해 보유 목록·다음 전투 손패에 나타나는지 확인한다.
3. 폰 스톰은 여러 전진 가능한 폰을 선택해도 비용이 1이어야 한다. 거꾸로 입은 청바지는 양측 나이트·비숍 계열 제거를, 신성 영역 전개는 비숍 희생 뒤 남은 아군의 가호 표시를 보여야 한다. 리미터 해제는 코스트 6을 모아 사용하며 대상에 즉시 남은 이동 3→2→1을 표시해야 한다. 세 번째 이동 직후 대상이 사망하고 턴이 넘어가야 한다.
4. 일시 강화 카드를 사용해 기물을 한 기 선택하고 경로를 고르면 손패 비용 원형이 `1`로 바뀌어야 한다. 두 기를 고르면 `2`가 되어야 한다. 취소하면 마나·보드·손패가 그대로이고, 확정 후 새 기물 SVG와 일시 강화 배지·효과 목록이 나타나야 한다. 다음 전투에는 영구 종류만 유지된다.
5. 선공권 획득 후 다음 전투에는 남은 적 턴 `10회`가 보이며 한 적 턴 후 `9회`가 된다. 아이스크림은 첫 플레이어 턴 코스트 3, 다음 턴에는 사용하지 않은 잔액에 3이 더해진다. 진형 책 3종의 같은 표지 양식과 다른 문양도 비교한다.
6. 휴식 노드에서 룩·비숍·나이트·퀸을 고른다. 신규 분기 기물마다 미리보기 SVG가 뜨고, 잠긴 경로에는 필요한 영구 기물 이름이 보여야 한다. 확대·축소해 여러 연결선이 노드를 가리지 않는지 확인한다. 한 경로를 확정하고 이후 전투에서 해당 이미지와 규칙을 확인한다.
7. 보스까지 진행한 뒤 새로고침하여 **저장된 원정 이어하기**를 누른다. 기물 위치, 카드·유물, 현재 상태와 강화 기록이 동일해야 한다. 390px 너비에서도 페이지 전체의 가로 스크롤은 없어야 한다. 손패가 많을 때는 손패 영역 내부에서만 가로 스크롤한다.

재현 가능한 실제 명령 기보와 기대 위치는 `crates/chesslayer/tests/fixtures/` 및 `web/tests/`에 있다. 신규 카드·유물·기물 규칙의 정확한 조건은 각각 `docs/content/adding-cards.md`, `docs/RELICS.md`, `docs/COMPOSITE_PIECES.md`를 따른다.

## 남은 제한

구행과 이전부터 사용한 기본 기물 등의 외부 추출 SVG는 재배포 권한이 확인되지 않았다. 이번 단계에서 만든 26개 신규 기물 SVG 및 카드·유물 그림은 직접 작성한 벡터다. 기존 구형 이미지의 권리 확인 또는 교체는 공개 배포 전에 필요하다. 저장은 브라우저 로컬 저장소에만 존재하며 다른 기기와 동기화되지 않는다.
