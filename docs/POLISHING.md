정의된 8종의 행마 자체는 이미 구현되어 있었다. 누락된 확정 기물은 발견하지 못했다. `adding-pieces.md`의 무희는 명시적으로 미등록 예제이므로 콘텐츠에 추가하지 않았다. 룩·퀸·템페스트를 적 편성에 새로 넣거나 아마존을 아군 강화로 주는 경로도 문서에 없으므로 만들지 않았다.

실제로 보완한 부분:

- 각 기물 정의에 능력 설명을 두고, 폰 정의에 강화 대상·효과·선행 조건을 둔다. 휴식 실행과 UI 경로가 같은 정의를 참조한다.
- 부활/강화 후 보드를 재구성할 때 지속 상태에서 가호 집합과 이동 이력을 다시 동기화한다. 비포획 제거로 죽었다가 부활한 기물의 가호가 다음 전투까지 보이지 않던 불일치를 수정했다.
- 기물 종류·강화 이력·가호·현재 위치·원래 위치를 휴식 스냅샷에 제공한다. 미리보기는 이 값을 읽기만 한다.

## 휴식 조작

기존 하단 강화/부활 목록을 제거했다. 중앙 보드는 유지하고 우측에 쉼터 패널을 배치한다.

1. 살아 있는 아군을 선택하면 해당 칸과 이미지를 강조·확대하고 능력 및 정의된 강화 경로를 보여준다.
2. 일반 폰의 경로를 선택하면 템페스트 결과를 미리 보여준다. `강화 확정`에서만 Rust 명령을 실행한다.
3. 초기 빈칸에 해당하는 사망 기록이 있으면 실제 기물의 이미지·이름·효과와 “이 기물을 되살리시겠습니까?”를 표시한다. `부활 확정`에서만 실행한다.
4. 취소/닫기/Esc는 선택만 해제한다. 부활 불가 빈칸·적 위치를 클릭해도 선택이나 오류 메시지를 변경하지 않는다.
5. 기존대로 노드당 행동은 한 번이다. 확정 후 맵으로 복귀하고 다음 전투가 변경된 진형을 받는다. 행동 없이 출발도 가능하다.

강화 후 단계인 템페스트를 선택하면 완료된 경로를 비활성 상태로 보여준다. 경로가 없는 종류는 그 사실만 설명한다. 비용은 쉼터 행동 1회이며 추가 재화는 없다. 현재 규칙에서는 인스턴스별 초기 위치가 고유하므로 같은 칸의 부활 후보는 최대 한 기지만, 패널은 여러 합법 후보가 제공되는 경우의 선택도 처리한다.

규칙 해석: 기존 강화에는 아군의 현재 랭크 제한이 없다. 전투 후 적진에 남은 아군도 기존대로 선택할 수 있도록 ‘자기 진영’을 소유자 기준으로 해석했다. 부활 위치는 임의의 아군 구역이 아니라 원정 시작 당시 그 기물의 정확한 초기 칸이다. 기존 기록과 다른 기물을 생성하지 않는다.

선택한 타일만 확대하고 전체 보드를 확대하지 않는다. 모바일에서는 보드와 패널을 세로로 배치하고, 패널을 스크롤할 때 보드를 고정해 선택 위치를 유지한다. 모션 줄이기 설정을 존중한다. 전투 이동/카드 대상 선택과 휴식 선택 상태는 분리되어 있다.

## 저장

기존 프로젝트에는 저장이 없었다. 이번 요청의 저장/재개 조건을 위해 브라우저 localStorage에 단일 원정을 저장한다. 키는 `chesslayer.run.v1`이다. Rust/WASM이 초기 캐릭터 ID·시드·성공한 모든 명령(적 행동 포함)을 버전 1 JSON으로 내보내고, 이어하기 때 같은 엔진으로 재생한다. 임의 보드를 불러오는 API는 추가하지 않았다.

미리보기·취소는 명령을 전송하거나 저장을 갱신하지 않는다. 확정 결과는 매 명령 직후 저장되며 카드 더미·맵·강화·부활·AI 난수 상태가 함께 복원된다. 새로고침 후 홈의 `저장된 원정 이어하기`로 재개한다. 손상된 기록/알 수 없는 버전은 거부하며 현재 엔진을 교체하지 않는다. 저장 실패는 플레이를 중단하지 않고 화면에 알린다. 새 원정은 기존 저장 하나를 대체한다.

서버 저장·다중 슬롯·기기 간 동기화는 없다. 이력 재생 방식이므로 향후 규칙/콘텐츠/난수 동작 변경 시 저장 버전을 올리거나 마이그레이션해야 한다.

휴식 E2E는 초기 보드 스냅샷을 위조하지 않는다. 기존 기보의 명령을 production WASM에 전달하고 필요한 적 턴을 실행해 만든 합법적 저장을 사용한다. 부활 테스트에서는 두 번째 전투의 실제 청바지 카드를 사용해 메이저 기물을 제거하고, 없어진 퀸 이동 대신 h2→h3을 수행해 정상적으로 쉼터까지 진행한다.

실행:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo check --workspace --target wasm32-unknown-unknown
npm run wasm --prefix web
npm run build --prefix web
CHESSLAYER_CHROME=/usr/bin/google-chrome npm run test:e2e --prefix web
```

이 환경에서는 읽기 전용 wasm-pack 캐시 때문에 최초 `npm run wasm`의 바인딩 도구 탐색이 실패했다. 이미 설치된 동일 버전의 CLI를 사용해 release WASM에 바인딩을 생성했다. 외부 설치는 하지 않았다.

```sh
cargo build -p chesslayer-web --target wasm32-unknown-unknown --release
/tmp/chesslayer-tools/bin/wasm-bindgen --target web --out-dir web/src/wasm target/wasm32-unknown-unknown/release/chesslayer_web.wasm
```

Rust 35개와 브라우저 7개, fmt/clippy/WASM target 검사, TypeScript/프로덕션 빌드가 통과했다. 부활 E2E 첫 시도는 테스트가 청바지가 버려진 턴에서 카드를 찾는 오류로 실패했으며, 실제 첫 손패 시점에서 사용하도록 기보 준비를 고쳐 통과했다. Chrome/localhost는 샌드박스 밖 실행 권한으로 검증했다. 이미지의 실제 로드와 화면 캡처도 확인했다.

캡처 위치는 `web/test-results/rest-upgrade-desktop.png`, `rest-revive-mobile.png` 및 기존 전투/맵 스크린샷이다. 다음 E2E 실행 시 테스트 결과 폴더가 갱신된다.

## 남은 사항

별도 기획서가 제공되면 추가 기물·능력·강화 분기를 같은 정의 구조에 추가해야 한다. 현재 문서에 없는 능력을 추정해 구현하지 않았다. 제공 이미지의 재배포 권한 확인은 남아 있다. 기존의 체크메이트/캐슬링/앙파상/자동 승격 미지원, 고정 카드 보상, 단순 AI 등은 이번에 규칙을 변경하지 않았다.
