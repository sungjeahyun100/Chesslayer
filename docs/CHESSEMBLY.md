# Chesssembly 식의 작동 방식

Chesssembly는 기물의 이동과 조건을 명령식으로 기술합니다. `Program::parse(source)`가 식을 검사해 프로그램으로 만들고, `Program::execute(&board, origin)`이 입력 보드를 바꾸지 않은 채 순서가 있는 액션 후보를 생성합니다. `interpret(&board, origin, source)`는 두 단계를 한 번에 수행합니다. 후보를 실제 보드에 적용하는 함수는 `chessembly::apply_default_action`입니다.

## 공통 실행 규칙

- 명령은 공백으로 구분합니다. `;`는 독립된 체인을 시작하고 `#`부터 줄 끝까지는 주석입니다.
- 각 체인은 기물이 있는 `origin`에서 시작합니다. 탐색 좌표도 `origin`, 조건은 참입니다. 레지스터와 앵커 슬롯은 비어 있고 변환 이름은 없습니다. 다음 체인과 다음 실행에는 이 상태가 이어지지 않습니다.
- 상대 좌표 `(dx,dy)`는 **현재 탐색 좌표** `(file,rank)`를 기준으로 합니다. 실행 기물의 방향이 `d`일 때 목표 칸은 `(file + dx × d, rank - dy × d)`입니다. `d=+1`이면 `dy=1`은 보드 위쪽이며, `d=-1`이면 두 축 모두 반전됩니다.
- 조건이 거짓이면 일반 식은 실행되지 않습니다. 최상위에서는 체인을 끝내고, 블록 안에서는 닫는 괄호로 건너뜁니다. `not`, `true`, `false`, `write`, `read` 계열, `while`, `jmp`, `jne`, `label`은 거짓 조건에서도 실행됩니다. 검사식은 이전 조건과 자동으로 AND 하지 않고 조건을 **검사 결과로 대체**합니다.
- 탐색 좌표는 후보의 실제 출발 칸이 아닙니다. 액션의 `from`은 항상 `origin`입니다. 앞선 후보를 보드에 적용하고 다음 식을 평가하지 않습니다.
- 보드 밖과 플레이 가능 마스크에서 제외된 칸에 대한 일반 좌표식은 조건을 거짓으로 만듭니다. 경계 검사식은 그런 칸을 조사할 수 있습니다.

## 이동·포획·탐색 식

아래에서 `q`는 현재 탐색 좌표에 `(dx,dy)`를 적용한 목표 칸입니다. '실패'는 조건을 거짓으로 설정한다는 뜻입니다. 모든 식은 조건이 참일 때만 실행됩니다.

| 식 | 검사와 탐색 좌표의 변화 | 만드는 후보 |
| --- | --- | --- |
| `move(dx,dy)` | `q`가 비어 있으면 그곳으로 탐색 좌표를 옮깁니다. 기물이 있으면 실패합니다. | 빈 칸에서 `Move` |
| `take-move(dx,dy)` | 아군이 있으면 실패합니다. 빈 칸이나 적이 있으면 `q`로 옮깁니다. 적이 있으면 후보를 만든 **뒤** 조건이 거짓이 됩니다. | 빈 칸·적 칸에서 `TakeMove` |
| `take(dx,dy)` | 아군이면 실패합니다. 적이면 `q`로 옮기고 포획 위치를 기억합니다. 빈 칸에서도 `q`로 옮기지만 후보는 만들지 않습니다. | 적 칸에서 `Take` |
| `jump(dx,dy)` | 같은 프레임에서 앞서 성공한 `take`가 있어야 합니다. 그 후 현재 좌표에서 계산한 `q`가 빈 칸이고 현재 칸과 달라야 합니다. 성공하면 `q`로 옮기고, 아니면 실패합니다. | 기억한 적을 포획하고 빈 `q`로 이동하는 `TakeJump` |
| `catch(dx,dy)` | `q`에 적이 있어야 합니다. 탐색 좌표는 그대로입니다. | 적을 제거하고 출발 칸에 머무는 `Catch` |
| `shift(dx,dy)` | 탐색 좌표를 `q`로 옮깁니다. 기물이 있으면 교환 후보를 만들고, 빈 칸이면 후보 없이 계속합니다. 아군·적군 모두 대상이 됩니다. | 기물이 있으면 `Shift` |
| `peek(dx,dy)` | 빈 칸일 때만 탐색 좌표를 `q`로 옮기고, 기물이 있으면 실패합니다. | 없음 |
| `observe(dx,dy)` | 빈 칸이면 계속하고, 기물이 있으면 실패합니다. 탐색 좌표는 그대로입니다. | 없음 |
| `anchor(dx,dy)` | 유효한 `q`로 탐색 좌표를 옮깁니다. 기물이 있는 칸도 가능합니다. | 없음 |
| `reflect-ray(dx,dy)` | 현재 탐색 좌표에서 광선을 시작합니다. 경계나 `wall-piece` 앞에서 x 또는 y 성분을 반전해 두 경로를 계속 탐색하고, 같은 `(위치, 진행 벡터)`를 다시 방문하면 끝냅니다. | 빈칸·적 칸에서 `TakeMove`; 적 포획 뒤에는 진행하지 않음 |

예를 들어 `take(1,0) jump(1,0)`은 첫 칸의 적을 포획하고 그 다음 빈 칸에 착지하는 후보를 만듭니다. 이때 앞서 생성한 해당 `Take` 단독 후보 하나를 제거하고 `TakeJump` 후보로 바꿉니다. 생성된 후보가 실제로 적용 가능한지는 액션 적용 단계에서도 검사합니다.

## 기물·색상 검사식

이 식들은 조건을 검사 결과로 설정하며 좌표나 후보는 바꾸지 않습니다. 이름은 보드 카탈로그의 이름과 비교합니다.

| 식 | 참이 되는 경우 |
| --- | --- |
| `piece(name)` | `origin`에 있는 실행 기물의 종류가 `name`일 때 |
| `color(name)` | 실행 기물의 색상 이름이 `name`일 때. 현재 턴은 검사하지 않습니다. |
| `piece-on(name,dx,dy)` | `q`에 있는 기물의 종류가 `name`일 때 |
| `color-on(name,dx,dy)` | `q`에 있는 기물의 색상 이름이 `name`일 때 |
| `enemy(dx,dy)` | `q`에 소유자가 다른 기물이 있을 때 |
| `friendly(dx,dy)` | `q`에 소유자가 같은 기물이 있을 때 |

대상 칸이 비어 있으면 `piece-on`, `color-on`, `enemy`, `friendly`는 모두 거짓입니다.

## 경계 검사식

경계식은 `q`의 경계 상태로 조건을 대체하며 좌표나 후보를 바꾸지 않습니다. 방향 `-1`인 기물에는 위·아래와 왼쪽·오른쪽의 뜻을 모두 뒤집어 적용합니다.

| 식 | 참이 되는 경우 |
| --- | --- |
| `bound(dx,dy)` | `q`가 보드 밖이거나 플레이 가능 마스크에서 제외될 때 |
| `edge(dx,dy)` | `q`가 한 방향으로만 보드 밖일 때 |
| `corner(dx,dy)` | `q`가 가로·세로 두 방향으로 보드 밖일 때 |
| `edge-top(dx,dy)`, `edge-bottom(dx,dy)`, `edge-left(dx,dy)`, `edge-right(dx,dy)` | 지정한 단일 방향으로 보드 밖일 때 |
| `corner-top-left(dx,dy)`, `corner-top-right(dx,dy)`, `corner-bottom-left(dx,dy)`, `corner-bottom-right(dx,dy)` | 지정한 두 방향으로 보드 밖일 때 |

방향별 식에도 반드시 `(dx,dy)`를 적습니다. 마스크에서 제외된 칸은 `bound`에는 해당하지만 방향이 없어서 `edge`나 `corner`에는 해당하지 않습니다. 예를 들어 왼쪽 끝 칸에서 `edge-left(-1,0)`은 참입니다.

## 좌표 지정·저장 식

| 식 | 동작 |
| --- | --- |
| `absolute(x,y)` | 탐색 좌표를 절대 칸 `(x,y)`로 바꿉니다. |
| `absolute-x(x)` | 파일만 절대 `x`로 바꾸고 랭크는 유지합니다. |
| `absolute-y(y)` | 랭크만 절대 `y`로 바꾸고 파일은 유지합니다. |
| `write-anchor(n)` | 현재 탐색 좌표를 앵커 슬롯 `n`에 저장합니다. |
| `read-anchor(n)` | 앵커 슬롯 `n`의 좌표로 탐색 위치를 복원합니다. |

절대 좌표식은 방향 `-1`일 때 지정한 축을 보드 반대편 기준으로 뒤집습니다. X는 `width - 1 - x`, Y는 `height - 1 - y`입니다. 계산한 칸이 보드 밖이거나 마스크에서 제외되면 기존 좌표를 유지하고 조건을 거짓으로 만듭니다. 이후 `true`나 `not`으로 조건을 복구하면 기존 좌표에서 이어집니다.

앵커 슬롯은 체인마다 독립적인 `0..=255`번입니다. 초기화 전 읽기는 `UninitializedAnchor(n)` 오류입니다. 블록 안에서 저장한 앵커는 블록 밖에서도 읽을 수 있지만, 블록 안에서 복원한 *탐색 좌표 자체*는 블록을 나올 때 사라집니다. 앵커 식은 조건이 거짓일 때 실행되지 않습니다.

예를 들어 `write-anchor(0) anchor(-1,0) read-anchor(0) move(-1,0)`은 잠시 왼쪽 칸을 탐색한 뒤 저장한 원점으로 돌아와 왼쪽 이동 후보를 만듭니다.

## 조건·레지스터 식

| 식 | 현재 조건에 미치는 영향 |
| --- | --- |
| `true` | 참으로 설정 |
| `false` | 거짓으로 설정 |
| `not` | 참과 거짓을 반전 |
| `write(n)` | 현재 조건을 레지스터 `n`에 저장하고 조건은 유지 |
| `read(n)` | 저장된 값으로 조건을 대체 |
| `read-and(n)` | 현재 조건과 저장된 값의 논리 AND로 대체 |
| `read-or(n)` | 현재 조건과 저장된 값의 논리 OR로 대체 |
| `read-xor(n)` | 현재 조건과 저장된 값의 논리 XOR로 대체 |

레지스터도 체인마다 독립적인 `0..=255`번입니다. `write`와 `read` 계열은 조건이 거짓이어도 실행되므로 거짓을 저장하거나 저장값으로 조건을 복구할 수 있습니다. 초기화 전 읽기는 `UninitializedRegister(n)` 오류입니다. `false true move(-1,0)`은 후보를 만들 수 있지만 `false move(-1,0) true`는 `move`에서 체인이 끝납니다. 이 식들은 직접 후보를 만들지 않습니다.

## 블록·반복·분기 식

| 식 | 작동 방식 |
| --- | --- |
| `{ ... }` | 부모 조건이 참일 때만 들어갑니다. 자식 프레임은 부모의 좌표와 포획 기억을 복사하고 조건 참으로 시작합니다. 닫는 괄호에서 자식의 좌표·조건·포획 기억은 사라집니다. 슬롯·변환 이름·후보는 체인에서 공유합니다. |
| `do ... while` | 본문 실행 후 `while`에서 조건이 참이면 `do` 다음 식으로 돌아갑니다. 거짓이면 반복을 끝냅니다. 두 경우 모두 `while`을 지난 조건은 참입니다. `do while`처럼 본문이 비어 있으면 건너뜁니다. |
| `repeat(n)` | 현재 식의 위치에서 `n`을 뺀 위치로 이동합니다. 양수는 이전 식으로, 음수는 다음 식으로 이동하며 0은 같은 식을 다시 실행합니다. 반복 횟수가 아니라 **이동 거리**입니다. 조건이 거짓이면 실행되지 않습니다. |
| `label(n)` | 같은 체인 안의 점프 목적지를 표시합니다. |
| `jmp(n)` | 현재 조건이 참이면 `label(n)`으로 이동합니다. 거짓이면 이동하지 않고 조건을 참으로 복구합니다. |
| `jne(n)` | 먼저 조건을 반전한 뒤 `jmp(n)`과 같이 작동합니다. 원래 거짓이면 점프하고, 원래 참이면 다음 식으로 진행하며 조건을 참으로 복구합니다. |
| `end` | 현재 체인을 즉시 끝냅니다. |

정의되지 않은 라벨, 중복 라벨, 짝이 맞지 않는 블록이나 `do`/`while`은 파싱 오류입니다. `repeat(n)`의 목적지가 체인 범위 밖이면 실행 중 `Parse("invalid repeat")` 오류입니다. `move(-1,0) repeat(1)`은 탐색 좌표를 갱신하며 `move`를 다시 평가해 빈 칸이 이어지는 동안 각 칸의 후보를 순서대로 만듭니다.

## 변환과 액션 적용

`transition(name)`은 이후 생성한 후보에 변환할 기물 종류를 기록합니다. 인자 없는 `transition` 또는 `transition()`은 이후 후보의 변환 설정을 지웁니다. 이미 만든 후보에는 영향을 주지 않습니다. 해당 이름이 카탈로그에 있는지는 후보를 **적용할 때** 검사합니다. 블록 안에서 설정한 변환도 같은 체인 바깥에 남습니다.

후보는 `DefaultAction { first, continuation }` 형식입니다. 각 `ActionStep`에는 `from`, `take`, `move_to`, `effect`, 선택적 `transition`이 있습니다. Chesssembly가 직접 만드는 후보는 한 단계짜리이고 `continuation`은 비어 있습니다. `from`은 실행 원점, `take`는 포획·교환할 칸, `move_to`는 최종 칸입니다.

| 효과 | 적용할 때 일어나는 일 |
| --- | --- |
| `Move` | 빈 `move_to`로 이동 |
| `TakeMove` | 빈 칸이면 이동하고 적이 있으면 포획하며 이동 |
| `Take` | `take == move_to`의 적을 포획하며 이동 |
| `TakeJump` | `take`의 적을 포획하고 별도의 빈 `move_to`로 이동 |
| `Catch` | `take`의 적을 제거하고 `from`에 머무름 |
| `Shift` | `from`과 `move_to`의 기물을 교환 |

후보는 체인 순서와 식 실행 순서대로 반환됩니다. `apply_default_action`은 효과의 조건을 다시 검사하고, 연속 단계가 실패하면 이미 적용한 변경도 되돌립니다. 룰 모듈은 후보를 추가로 거부하거나 자체 게임 상태를 갱신할 수 있습니다.

## 오류와 지원 범위

인자 개수 오류, 정수가 아닌 좌표, `i32` 범위를 벗어난 숫자, 슬롯 범위 밖 번호는 `Program::parse`에서 `Error::Parse`가 됩니다. `origin`에 기물이 없으면 `EmptyOrigin`입니다. 한 체인에서 100만 명령을 넘으면 `ExecutionLimit`, 블록 깊이가 한계에 닿으면 `BlockLimit`입니다.

`danger(dx,dy)`는 `unsupported expression: danger` 파싱 오류를 반환합니다. `check`, `state`, `set-state`, `if-state`도 현재 지원하지 않아 파싱 오류가 납니다.

동작 예시는 `crates/chessembly/tests/behavior.rs`와 `crates/chessembly/tests/commands.rs`에서, 액션 순서와 적용 후 보드 결과는 `crates/chessembly/tests/fixtures/action_snapshots.txt`에서 확인할 수 있습니다.

## 체인별 반사벽 설정

`wall-piece(key)`는 현재 체인에서 `take-move`가 해당 종류 앞에서 정지하게 한다. 소유자와 무관하며, 그 칸에 후보를 내거나 탐색 좌표를 옮기지 않고 조건을 거짓으로 만든다. 설정은 블록에서 공유되지만 다음 세미콜론 체인에서 초기화된다. `move`, `take` 등 다른 효과와 기존 `edge` 의미는 바꾸지 않는다.

`barrier(dx,dy)`는 해당 상대 칸이 보드 밖/마스크 밖이거나, `wall-piece`로 지정한 종류에 점유되어 있을 때 참이다. 두 식의 조합으로 일반 DSL의 분기·반복을 이용해 반사 경로를 정의한다. 바운싱의 구체적인 경로 선택과 종료 의미는 [VARIANTS.md](VARIANTS.md#반사의-실제-해석)를 참고한다.
