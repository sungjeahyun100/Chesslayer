- 부대 선택 화면의 `개발자 모드 · 전체 해금`은 사용자 요청으로 추가한 플레이 확인용 버튼이다. 5개 부대·4개 층을 즉시 개방하고 기존 영구 해금 저장소에 보존한다. 현재 원정 기록은 변경하지 않는다.
- 보스 격파 시 바로 런 종료 및 영구 해금. 동일 런에서 층 이동하거나 사망자 전체를 부활시키지 않는다. 시작 화면에서 해금된 층을 선택해 새 런을 시작한다.
- 모든 보상 경로와 보물에서 부대별 카드·유물풀을 분리했다. 카드 종류가 3개 미만인 임시 부대만 보상 슬롯에 같은 종류가 중복될 수 있다. 미정 유물풀은 다른 부대의 유물 대신 자기 부대 카드로 대체한다.
- 브라우저 런 저장은 `chesslayer.run.v1`의 버전 15(`squad`, `floor`, `seed`, 정상 명령 기록), 영구 해금은 별도 `chesslayer.progress.v1`이다. 새 런은 해금을 지우지 않는다. 이전 버전 런은 안내 후 재생을 거부하며 새 런을 시작하기 전까지 원본을 보존한다. 해금/저장은 브라우저·접속 주소별이다.

## 핵심 규칙과 UI

살아 있는 식재료를 직접 포획하면 공격자는 원래 칸에 남고 대상 칸만 시체가 된다. 같은 행동으로 시체를 다시 먹지 않는다. 시체는 별도 종류이며 양측이 먹을 수 있다. 일반 시체 포획은 목적지로 이동하고, 배달된 만찬은 제자리에서 먹는다. 로얄 직접 포획 및 기존 호신용품 승패를 먼저 판정한다.

축복은 시체 포획자에게 민첩 3, 비축복은 시드가 있는 50:50 광기/죄책감 판정을 준다. 광기 3은 전향·축복, 죄책감 2는 영구 전투불능이다. 전투불능은 이동·능력을 막고 휴식의 고해성사만 해제한다. 일반 부활도 이 상태를 없애지 않는다.

허기는 기물별로 전투를 넘어 지속된다. 정상은 전투 종료만으로 공복이 되지 않으며, 이미 발생한 허기만 악화한다. 합법적인 시체 포획이 있을 때 굶주림은 생명체 포획을, 기아는 시체 이외의 행동을 막는다. 시체 포획은 정상으로, 식당 식사는 아군 전체를 정상으로 회복한다.

웃는 왕의 범위별 드로우·마나, 귀부인의 제물, 수레의 시체 통과·이동, 사제의 다른 아군 지원, 무희·신도의 시체 전용 행마 및 허기 유발을 적용한다. 선택형 발동 효과는 보드에서 대상을 선택해야 다음 행동을 할 수 있다. 마지막 접시와 충원은 전투 후 대상 선택 창을 사용한다. 귀부인/사격은 기물 선택 후 능력 버튼, 대상 기물 순으로 조작한다. 사격 명중률은 대상별로 표시한다.

보스 종소리는 적 턴 종료를 한 주기의 완료로 보고, 2·5주기에 예고하고 3·6주기에 발동한다. 허기가 높은 비로얄을 우선하고 동률은 시드 난수로 고른다. 흑의 첫 시체 포획 3회에는 실제 포획자에게 민첩 1을 더한다.

포병의 탄약은 일반 마나 회복 경로로 충전되지 않는다. 창고 포획/파괴마다 200 감소, 상하좌우 양측 기물이 사망하며 인접 창고도 연쇄 폭발한다. 창고 전멸이 패배 조건이고 보스 격파 시 남은 창고의 한계치까지 보급한다. 일반 강화 대신 휴식/엘리트 보상의 창고 강화로 보유 탄약의 10%를 추가한다.

보드의 주요 상태 배지, 선택한 기물의 전체 상태/능력, 고해성사, 전투 후 선택, 탄약·한계치, 해금 안내를 기존 UI에 통합했다. 데스크톱은 보드·손패·턴 버튼이 화면 안에 들어오도록 높이에 맞추며, 모바일 턴 버튼과 자원은 하단에 고정한다. 기물별 임시 SVG는 기존 같은 계열 이미지를 재사용하고 시체만 별도 표식으로 구분한다. 새 카드/유물은 기존 그림을 임시로 재사용한다.

## 미구현·불완전한 영역과 다음 기획

- 부족의 독재자: 정의되지 않은 보스전은 만들지 않았다. 4층 승리 뒤 별도 최종 전투는 없다.
- 특수부대 상세 콘텐츠, 포병 고유 행마·특수능력·추가 카드·유물, 선봉대 빈 기물 슬롯/프로모션 풀, 이단 신도 프로모션, 1·3·4층 보스 전용 능력은 기획 확정 후 교체해야 한다.
- 기존 작업 브랜치에는 상점·화폐·일반 이벤트 엔진이 없었다. 요청에 정의된 식당만 추가했으며 새 상점 경제 시스템은 창작하지 않았다.
- 사격 거리·사거리·엄폐·비용, 왕 전향, 허기와 카드 재배치의 범위, 창고 강화 상한/반올림, 임시 시작 덱, 보스 및 신규 능력/카드의 밸런스는 미확정이다.
- 아트는 기존 SVG 재사용이다. 동일 계열이 같은 그림을 쓰므로 이름/상태/능력 정보로 구분한다. 원본 에셋의 기존 출처·권한 상태는 `docs/ASSETS.md`를 따른다.
- 서버 저장/계정 동기화는 없고 기존 로컬 저장을 사용한다. 기존 v14 런의 자동 마이그레이션은 제공하지 않는다.

## 검증

새 프레임워크 없이 기존 Cargo·Playwright를 사용했다. 새 Rust 검사는 `crates/chesslayer/tests/v03.rs`의 7개 통합 시나리오이며, 목적은 다음과 같다.

1. 모든 부대·층 진입, 카드/유물 소속 분리, 개정 보스 편성.
2. 식재료 포획 제자리 유지 → 별도 시체 → 이동 포획, 기아 제한, 같은 진영 시체, 무희의 시체 전용 포획, 로얄 우선 판정.
3. 시드별 광기/죄책감 두 결과, 전향, 영구 전투불능, 수레의 시체 통과.
4. 전투 후 허기 지속·악화, 고해성사·식당 분리, 이동 없는 만찬.
5. 민첩·다음 소속 턴 약화·영구 하락·기본 이하 사망, 탄약 무회복 및 창고 폭발·게임 오버.
6. 명중률 경계, 권총 실제 처리, 잘못된 카드 선택 원자성, 종소리 예고 및 3·6주기 발동.
7. 선봉대 보병 5종의 아군·적군 합법 이동 전체 비교, 대각선 중간 차단·포획 후 정지와 나이트 도약 구분.

`web/tests/v03.spec.ts`의 2개 시나리오는 네 부대의 정상 15단계 완주 기보를 WASM에서 재생하고 마지막 플레이어 수를 실제 보드 클릭으로 수행한다. 영구 해금, 새로고침, 다음 부대·층 선택, 네 신규 부대 카드 조작, 상태, 탄약, 모바일 고정 조작을 검사한다. `fixtures/v03-*.json`은 실제 공개 `Game::dispatch`와 공통 적 AI로 생성한 정상 명령 기록이다. 생성용 임시 도구는 제품/저장소에 추가하지 않았다. 기존 수호자 카드·휴식·승격·보상·저장 검사를 유지했고 새 진행 규칙에 의존하는 기대값만 갱신했다.

```sh
cargo test --workspace
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo check --workspace --target wasm32-unknown-unknown
npm run wasm --prefix web
npm run build --prefix web
CHESSLAYER_CHROME=/usr/bin/google-chrome npm run test:e2e --prefix web
```

현재 환경은 이미 설치된 `/tmp/chesslayer-tools/bin/wasm-bindgen`으로 release WASM 바인딩을 생성했다. 일반 환경에서는 `npm run wasm --prefix web`을 쓰면 된다. 최종 확인 결과는 아래와 같다.

## 선봉대 보병 행마 수정

기획서의 `color(white/black)`과 현재 게임 보드의 `player/enemy` 이름이 달라 색상 조건이 모두 실패하던 버그를 수정했다. 원문은 진영별 고정 방향으로 작성됐으나 현재 엔진은 이미 각 진영 기준 상대좌표를 사용하므로, 독립된 보병 스크립트마다 전방 행마를 상대좌표로 표현했다. 원문 기획과 DSL 엔진은 변경하지 않았다.

모두 상하좌우 1칸 이동·포획이 공통이다. 도끼는 전방 대각선 1~2칸, 장창은 전방 나이트 도약 4곳, 검은 장창+전방 대각선 1칸, 장창+도끼는 장창+전방 대각선 1~2칸이다. 권총은 검과 같은 행마에 사격을 더한다. 양 진영의 빈 보드에서 목적지 수 8·8·10·12·10 및 중간 차단/포획을 검사했다. 툴팁과 강화 설명에도 실제 행마를 표시한다. 기존 수호자 1층 완주 기보는 정상화된 선봉대 보스를 상대로 다시 생성했다.
