# 전투 엔진 최적화 검증 및 측정

## 회귀 검증

| 대상 | 방법 | 기대 결과 |
| --- | --- | --- |
| 공개 행동 API | `cargo test -p chesslayer stale_public_action_is_rejected_without_changing_battle` | 합법 행동 생성 후 보드를 바꾸면 `IllegalAction`을 반환하고 상태가 그대로 유지된다. |
| 중복 행동 | `cargo test -p chesslayer dedupe_tests` | 16개 이상 후보에서도 첫 경로 정보가 남고, 다른 승격 효과는 별도 행동으로 남는다. |
| 전투 규칙과 원정 재생 | `cargo test --workspace` | 기존 가호, 호신용품, 선공권, 리미터, 승격, 흡수, 복합 이동, 적 미리보기, 저장 명령 테스트가 모두 통과한다. |
| 기준 상태와 재생 결과 비교 | `winning-run.json`의 앞 14개 명령을 시드 2026으로 재생하고, 적 턴마다 `EnemyStep`을 실행한 뒤 각 명령의 `snapshot()` JSON을 비교 | 기준 상태와 변경 상태의 14개 스냅샷이 바이트 단위로 같다. |

마지막 비교는 작업 전 엔진 소스를 별도 임시 빌드에 보관하여 실행했다. `cmp` 결과가 같았다. 임시 비교용 실행 파일은 저장소에 포함하지 않았다.

## 성능 측정

`cargo run -p chesslayer --release --example engine_bench -- 10000`을 사용했다. 같은 호스트에서 작업 전후 release 바이너리를 번갈아 3회씩 순차 실행했고, 아래 값은 각 1만 회 평균의 **3회 중앙값**이다. 단위는 µs/회이며 낮을수록 좋다. 변경 전 상태는 이번 작업을 시작할 당시의 작업 트리(이미 존재하던 기물 관련 수정 포함)를 임시 복사한 것이다.

- 기본 배치: 8×8, 양쪽 표준 16기, 백 나이트 `b1`에서 `legal_actions()`와 `preview_actions()` 측정.
- 복잡 배치: 8×8, 양쪽 16기. 변형기물 7종과 킹을 전열에 놓고 백 `b4`에서 측정. 적과 인접해 포획·복합 행동 후보가 나온다.
- `public_apply_us`: 측정 전에 얻은 행동으로 공개 `apply_piece_action()`을 호출한다. 이 경로는 의도대로 재검증한다.
- `selected_move_us`: `Game::dispatch(Command::Move)`의 합법 행동 생성·선택·내부 적용·로그 처리를 함께 측정한다.
- `enemy_us`: `Game::dispatch(Command::EnemyStep)` 한 번이다.
- 상태 변경 측정에서는 `Battle`/`Game` 복제를 각 반복의 타이머 **밖**에서 수행했다. `legal_actions()`와 `preview_actions()`는 같은 읽기 전용 배치를 반복 사용했다.

| 배치 | 항목 | 전 (µs) | 후 (µs) | 변화 |
| --- | --- | ---: | ---: | ---: |
| 기본 | `legal_actions()` | 0.703 | 0.711 | 1.1% 느림 |
| 기본 | 공개 행동 적용 | 2.105 | 1.382 | 34.3% 단축 |
| 기본 | 선택된 이동 명령 | 3.399 | 1.586 | 53.3% 단축 |
| 기본 | `preview_actions()` | 2.112 | 0.790 | 62.6% 단축 |
| 기본 | `enemy_step` | 12.765 | 10.532 | 17.5% 단축 |
| 복잡 | `legal_actions()` | 1.943 | 2.056 | 5.8% 느림 |
| 복잡 | 공개 행동 적용 | 4.125 | 2.977 | 27.8% 단축 |
| 복잡 | 선택된 이동 명령 | 6.839 | 3.231 | 52.8% 단축 |
| 복잡 | `preview_actions()` | 8.828 | 2.161 | 75.5% 단축 |
| 복잡 | `enemy_step` | 30.047 | 29.285 | 2.5% 단축 |

`selected_move_us`는 순수 적용 함수만의 시간이 아니다. 요청된 실제 선택 경로 전체를 측정한 값이다. 합법 수 생성만의 비용은 `legal_actions()` 행에 분리해 기록했다. 작은 후보 목록에서는 해시 색인이 필요 없어 선형 중복 검사를 유지하고, 16개부터 색인을 구축한다. 이 변경은 위 두 배치의 순수 합법 수 생성 시간을 개선하지 못했으므로, 후보가 많은 별도 배치의 측정 전에는 그 부분의 이득을 단정할 수 없다.

## 남겨둔 복제와 검증

- 공개 `Battle::apply_piece_action()`은 외부 행동을 다시 검증한다. 내부에서 생성한 행동만 크레이트 내부 선택 경로로 전달된다.
- 연속 단계의 미리보기·포획 판정·가호 판정·실행은 실제 중간 상태를 확인해야 하므로 임시 보드를 사용한다.
- 카드 효과는 적용 후 로얄 보호를 확인하고 실패하면 취소해야 한다. `Battle::apply_effect()`의 카드용 보드 복제와 `Game::resolve_selection()`의 전체 `Battle` 복제는 이를 보장한다. 카드별 효과는 보드 외에도 가호·강화·플레이어 상태를 바꿀 수 있어 공통 제자리 롤백으로 단순히 바꾸지 않았다.
- 남은 비용은 모든 적 기물의 합법 행동 생성과 점수 계산, 복합 행동의 중간 보드 복제, 카드 선택의 전체 전투 복제다.
